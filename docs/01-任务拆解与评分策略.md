# 01 · 任务拆解与评分策略

> 先把"老师到底想看到什么"讲清楚，再动手。这份作业 60% 的分不在"电路画得好不好"，而在"你有没有真的造出一个会自我纠错的 Agent"。

---

## 一、题目本质

一句话：**写一个 Agent，把"帮我设计一块 Arduino 最小系统板"翻译成 KiCad 里能打开的原理图。**

难点不在电路（最小系统板是教科书级经典电路，示例库里就有），而在三件事：

1. **约束 LLM 的输出**——它天然会胡说八道、少引脚、编造型号，你必须用 Schema + 校验把它按住。
2. **把自然语言变成机器能用的结构**——BOM 和"引脚级连接"是两级抽象，很多人卡在只做了 BOM。
3. **闭环**——做完一步看结果、发现错就改，这才是"Agent"而不是"一次性调用"。

## 二、五步走（40 分，必做）

| 步 | 任务 | 真正的验收点 | 常见坑 |
|---|---|---|---|
| 01 | 环境搭建 | Python 3.10+ / KiCad 8 / LLM API 三者都通；课程模板工程能跑 | 卡在 KiCad 安装路径、API key 配错，浪费一周 |
| 02 | 自然语言 → BOM | 一句话 → 含型号/数量/位号/封装的清单，**型号必须是真实存在的** | 让 LLM 自由发挥，产出"100uF 陶瓷电容"这种不存在的组合 |
| 03 | 连接关系生成 | 引脚级结构（ref + pin → net），不是"电源接电源"这种废话 | 只输出"MCU 的 VCC 接电源"，没有 pin 号，无法落地 |
| 04 | 导入 KiCad | JSON → 真实 `.kicad_sch`，KiCad 打开不报错 | 直接拼 s-expression 但没内嵌 lib_symbols，打开是空框 |
| 05 | 交互修正 | 支持"把 C1 换成 100nF"→ 重新生成 → 差异可见 | 每次全量重生成，改了 A 崩了 B |

**每一步都要有独立的可运行入口**，答辩时能单独演示某一环。不要写成一个 `main.py` 800 行。

## 三、进阶挑战（20 分，选做）

| 挑战 | 难度 | 为什么推荐 / 不推荐 |
|---|---|---|
| **DRC 检查闭环** | ★★★ | **首推**。把 `src/validate.py` 扩成"跑检查 → 读错误 → 回填 Prompt → 重生成 → 再检查，直到通过"。代码量小、故事完整、演示效果强（能看到 Agent 自己改错） |
| 多 Agent 协作 | ★★★★ | 拆成 需求分析 / 设计 / 审查 三个角色互相"审稿"。适合想冲高分的组，但要处理好 token 成本 |
| 自动布局布线 | ★★★★ | 真正难在 KiCad 的 pcbnew API，8 周内风险高 |
| 仿真评测 | ★★★★★ | 需要 ngspice 等外部工具，只在有明确余力时做 |

> 建议：**基础 40 分先拿满，然后死磕 DRC 闭环**。20 分里拿 15 分，比同时开四个坑各拿 3 分划算得多。

## 四、交付物（少一样算未完成）

1. **代码仓库（含 README）**——标准是"助教按 README 5 分钟能跑起来"。所以 README 必须有：环境要求、安装步骤、一条能直接复制的运行命令、**不需要 API Key 也能跑的 mock 模式**。
2. **设计报告**——需求分析 / Agent 架构 / Prompt 设计思路 / 实验结果与失败案例分析。
3. **演示视频 3–5 分钟**——从输入一句话到 KiCad 打开原理图，全程真实录屏。
4. **答辩 PPT**——5 分钟讲清"你教会 AI 做了什么"。

## 五、10 分过程分怎么拿稳

老师原话：**每周进展以 commit 为证，仓库就是你的"成长日记"**。

这意味着过程分的判据是"commit 时间线的形状"，不是"最后一次性推上去的代码量"。所以：

- 每周至少 1 次 commit，且有可读的 message；
- commit 时间戳要分散在 8 周里，不能最后一周刷 50 个；
- `PROGRESS.md` 每周一行小结（做了什么 / 卡在哪 / 下周干什么）；
- 失败的尝试也要提交（`experiment: 试了直接拼 s-expr，KiCad 打开报错`）——这正是报告里"失败案例"的素材。

具体操作见 [05-Git留痕规范.md](./05-Git留痕规范.md)。
