# 04 · 答辩 5 分钟提纲

> 现场只有 5 分钟，讲不完所有细节。结构定死：**一句话定位 → 现场跑一遍 → 讲清一个技术决策 → 认一个短板**。
> 不要从头讲"什么是 Agent"，老师比你清楚。

---

## 时间分配（5:00）

| 时长 | 内容 | 要点 |
|---|---|---|
| 0:00–0:40 | **一句话定位 + 演示预告** | "我做了一个 Agent：输入'我要一块 Arduino 最小系统板'，它输出 KiCad 能打开的原理图。下面现场跑一次。" |
| 0:40–2:10 | **现场演示（真跑，不播视频）** | 输入需求 → 终端逐行输出 → `out/` 出现文件 → KiCad 打开 → 指一下 MCU、晶振、去耦电容 |

## 必须能现场回答的问题（提前准备）

1. **"为什么不用大模型直接生成 .kicad_sch 文本？"**
   → 试过。模型不保证 s-expression 语法与 UUID 唯一性，还要内嵌 `lib_symbols`，一次生成成功率极低，且报错信息无法回传给模型修正。改为：模型只负责**语义**（选什么器件、怎么连），**语法**交给确定性代码。

2. **"你怎么保证模型不胡说？"**
   → 三层：Schema 校验（格式）→ 器件白名单（型号真实存在）→ 网表自检（电气合理性）。任一层不过就带着错误信息重试。

3. **"这算 Agent 还是只是 prompt 调用？"**
   → 区别在**闭环**：它有工具（KiCad 导出、自检）、有反馈（错误列表）、有条件分支（重试 / 中止 / 报给用户）。单纯一次调用没有这些。

4. **"换一块更复杂的板子还行吗？"**
   → 老实说边界：常见小板可以，高速/射频不行。原因是白名单和约束规则没覆盖。

5. **"你个人做了哪部分？"**
   → 具体到文件，比如"`kicad_export.py` 我重写了三次，`validate.py` 和 Prompt 是我自己调的"，别含糊。

## 演示翻车预案

| 风险 | 预案 |
|---|---|
| 现场网络不通 / API 限流 | 提前录好 30 秒无剪辑片段，且 `--mock` 模式必须能跑完整链路 |
| KiCad 启动慢 | 提前把 KiCad 开着，只留新建窗口 |
| 生成结果和预期不同 | 不要现场 debug。说"这次它选了个替代方案，我说明一下差异"，然后转到你准备好的第二句需求 |
| 时间超了 | 砍掉 3:30–4:20 那段，直接到短板。**千万别砍现场演示** |

> "老师好，我做的不是一个画板工具，而是一个**把自然语言编译成电路**的 Agent。它最大的特点不是能生成，而是**生成错了会自己发现**。先看演示。"

## 讲技术决策时的示意图（口头描述即可）

```
需求文本
   │  ← 模型在这里有自由度，所以要用 Schema + 白名单按住
   ▼
BOM（型号/封装/位号）
   │  ← 模型在这里做"电气决策"，错在这里最贵
   ▼
网表（ref.pin → net）
   │  ← 到这里全部是确定性代码，模型不再参与
   ▼
.kicad_sch
```

**记忆点**："让模型做语义决策，让代码做语法落地。" 这句话讲出来，答辩就赢了一半。
