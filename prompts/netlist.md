# netlist.md — BOM → 引脚级连接表

## 流程位置
第 3 步。输入：`bom.json` + 原需求。输出：`netlist.json`（符合 `schemas/netlist.schema.json`）。

> 这是全流程**最容易糊弄、也最容易被扣分**的一步。判定标准只有一条：
> **每条连接必须能落到"某个器件的某个引脚号"**。"MCU 的电源接电源"这种是无效输出。

---

## Prompt 正文

```
你是硬件工程师。下面是元器件清单和原始需求，请给出引脚级连接方案。

原始需求：{requirement}
元器件清单：{bom_json}

要求：
1. 为每个器件分配真实引脚号。ATmega328P-AU(TQFP-32) 的引脚：
   VCC=4,6  GND=3,5,21  AVCC=18  AREF=20  RESET=29
   XTAL1=7(PB6)  XTAL2=8(PB7)
   PB0..PB5=12..17  PC0..PC5=23..28  PD0..PD3=30,31,32,1  PD4..PD7=2,9,10,11
   AMS1117-3.3(SOT-223) 的引脚：1=GND, 2=VOUT, 3=VIN
2. 每个网络（net）至少连接 2 个引脚，不得出现单端网络。
3. 同一引脚不得出现在两个网络中。
4. 网络命名：电源 +5V / +3V3 / GND，信号用功能名（如 LED_CTRL、RESET）。
5. 只列电气连接，不要描述布局建议。

只输出：
{
  "nets": [
    {"name": "+5V", "pins": [{"ref": "J1", "pin": "1"}, {"ref": "U1", "pin": "4"}]}
  ]
}
```

## 常见错误清单（写完自己对照）

| 错误 | 现象 | 怎么看出来的 |
|---|---|---|
| 漏去耦电容连接 | C2 在 BOM 里但网表里没出现 | `validate.py` 报"器件未连接" |
| 晶振只接一个脚 | Y1 的另一脚悬空 | 单端网络 |
| RESET 没上拉 | R1 悬空 | 单端网络 |
| GND 写成 VCC | — | 网络名混用检查 |
| 引脚号用文字 | `"pin": "VCC"` | Schema 要求 pin 为字符串数字 |

## 增量修正（revise.md 的要点，可并入本文件）

用户追问"把 C1 换成 100nF"时：

```
只修改与 C1 相关的部分，其余内容**原样返回**（包括顺序）。
输出必须仍满足 netlist schema。
改动处用 "changed": ["C1"] 标注。
```

> **不要每次全量重生成**。全量重生成会出现"改了 C1，C2 的值也跟着变了"的情况，
> 这是答辩时最容易被问倒的场景（"你这个 Agent 怎么保证稳定性？"）。
